# Copilot Instructions for TheWriterCo

## Project Overview
**TheWriterCo** is a comprehensive React + TypeScript application for Christian writings, biblical studies, and faith-driven services. The platform integrates AI-powered chat, Bible reading with text-to-speech, and a content creation system (Writer).

**Tech Stack:**
- **Framework:** React 18.3.1 with TypeScript
- **Build Tool:** Vite 6.2.1
- **State Management:** Redux Toolkit + Jotai (atoms)
- **UI Library:** Radix UI + Tailwind CSS
- **Backend Services:** Firebase (Auth, AI/Generative AI)
- **Testing:** Vitest + React Testing Library
- **Code Quality:** ESLint (TypeScript) + Prettier

---

## Repository Structure & Key Directories

### `/src/app/` - Global State Management
**Redux Slices** for centralized state:
- `store.ts` - Redux store configuration with localStorage persistence
- `reader/` - Bible reader state (chapter, verse, book, speech)
- `chat/` - AI chat state (messages, model selection, response constraints)
- `writer/` - Content creation state
- `page/` - Page navigation state (search, dismissals)
- `eBoundary/` - Error boundary state
- `cache/` - Cached data management

**Key Pattern:** Slices are persisted to localStorage via throttled subscriptions.

### `/src/pages/` - Route Pages
**Main application pages** (lazy-loaded):
- `ai/` - AI Chat interface with models, chat context
- `writer/` - Content editor with Monaco Editor integration
- `read/` - Documentation/Bible reading
- `kjv/` - King James Version Bible viewer
- `daily/` - Daily devotional with image carousel & ratings
- `number/` - Interactive number guessing game
- `root/` - Home page with Swiper carousel
- `login/` - Authentication page

### `/src/pkg/` - Reusable Components & Utilities
**Organized by domain:**
- `ai/` - Chat UI (ChatBox, Editor, Form, Models, MyPools)
  - Hooks: `useSendHandler`, `useBuildContexts`, `useResponseParser`, `useCommandHandler`
  - Integration with Firebase AI (Gemini)
- `firebase/` - Authentication, AI backend, analytics
  - `auth/` - Google/OAuth authentication with hooks
  - `ai/` - Gemini integration via Firebase
- `bible/` - Bible-related components (voice, chapters, verses)
- `button/`, `link/`, `frames/`, `flow/`, `voice/`, `writer/` - UI components
- `context/` - React Context providers (Theme)
- `hooks/` - Custom hooks for navigation, auth, data fetching
- `eboundary/` - Error boundary component

### `/src/page/` - Layout & Shell Components
- `Page.tsx` - Main layout wrapper (handles scrolling, page actions)
- `Header.tsx` - Navigation bar with search
- `Footer.tsx` - Footer component
- `Seo.tsx` - Helmet-based meta tags
- `Reader.tsx` - Bible reader sidebar
- `Block.tsx`, `Motion.tsx` - Layout utilities

### `/src/routes.tsx` & `/src/routing.tsx`
- Route definitions split into **protected** (auth required) and **public**
- Protected routes require Firebase authentication
- Suspended fallback states available

## Key Technologies & Patterns

### State Management
1. **Redux Toolkit** - Global persistent state
2. **Jotai Atoms** - Local UI state (e.g., modal visibility, typing status)
3. **localStorage** - Persistence layer via Redux subscriptions

### Authentication Flow
- **Firebase Auth** with Google OAuth
- `useUserLikelySignedIn()` hook - Checks auth state across app
- Protected routes via `AuthRouter` component
- Fallback: `Unauthenticated` view for unauthorized access

### AI Integration
- **Firebase Generative AI** (Gemini API)
- Context building from reader state + user preferences
- Response constraints: shorter | short | detailed
- System instructions fetched from GitHub repo
- Message parsing with command handlers

### Styling
- **Tailwind CSS** with custom config (`tailwind.config.js`)
- **Radix UI** for accessible components
- **Framer Motion** for animations
- **Custom Atoms** in `/src/pkg/*/atoms/`

### Type Safety
- Strict TypeScript configuration
- Type definitions in `**/types.ts` per module
- Config files export constants & defaults

### Testing
- **Vitest** with jsdom environment
- **React Testing Library** for component tests
- Setup file: `vitest.setup.ts`
- Mock Service Worker for API mocking

### Environment & Secrets

**Setup Instructions:**
1. Copy `.env.example` to `.env.local`
2. Update Firebase credentials in `.env.local` (get from Firebase Console)
3. Never commit `.env.local` to version control (already in `.gitignore`)

**Environment Variables:**
- All Vite environment variables must be prefixed with `VITE_` for client-side access
- Available in code via `import.meta.env.VITE_*`
- Type definitions in `src/vite-env.d.ts` for TypeScript support

**Configuration:**
- **Firebase Config** in `/src/pkg/firebase/config.ts`
  - Reads from env variables with fallback to defaults
  - API keys are public (client-side, no sensitive data)
  - Project ID: `thewritercompany`
  - Auth Domain: `secure.thewriterco.com`
- **Redux DevTools** in `/src/app/store.ts`
  - Enabled in development (`process.env.NODE_ENV === "development"`)
  - Disabled in production for security
- **Security:** Firebase security rules protect data at backend level

## Code Patterns & Best Practices

### Component Structure
```tsx
// Functional components with hooks
const MyComponent = ({ prop }: Props) => {
  const state = useSelector((s: RootState) => s.slice);
  const dispatch = useDispatch();
  const localState = useAtom(atom);
  
  return <JSX />;
};
export default MyComponent;
```

### Custom Hooks Pattern
- Hooks are in `hooks/` or `pkg/**/hooks/`
- Return objects with named functions: `{ buildContexts, ...}`
- Use `useCallback` for memoization
- Leverage Jotai atoms for state sharing

### Redux Slices
- Create slice with `createSlice`
- Define `initialState` in separate config file
- Export actions directly from slice
- Types in separate `types.ts` file

### Error Handling
- ErrorBoundary wraps App
- Error fallback component: `ErrorFallback`
- Error state in Redux: `eBoundary` slice
- Try-catch in async operations

### Async Operations
- Use Jotai for loading states
- Build contexts with user + reader + chat state
- Firebase functions handle backend logic
- Response parsing with `useResponseParser()` hook

## Common Development Tasks

### Adding a New Route
1. Create page in `/src/pages/{name}/index.tsx`
2. Add to `protectedRoutes` or `publicRoutes` in `/src/routes.tsx`
3. Wrap with `Page` component for layout
4. Use `useTransitionNavigation()` for smooth transitions

### Adding State Management
1. Create slice in `/src/app/{feature}/`
2. Add to Redux store in `/src/app/store.ts`
3. Add localStorage persistence if needed
4. Export types in `types.ts`

### Creating UI Components
1. Add to `/src/pkg/{category}/`
2. Use Radix UI + Tailwind for styling
3. Export with named exports + default
4. Add TypeScript interfaces

### Adding Firebase Integration
1. Create function in `/src/pkg/firebase/{feature}/`
2. Use Firebase SDK methods
3. Handle errors with try-catch
4. Integrate with Redux dispatch

## Communication Guidelines for Copilot

When assisting with this codebase:
1. **Always maintain TypeScript type safety** - Use proper interfaces from `types.ts`
2. **Follow Redux patterns** - Use `useSelector` + `useDispatch` consistently
3. **Preserve component structure** - Keep pages, components, utils organized as-is
4. **Reference state slices** - Know the current state shape in Redux
5. **Use Radix UI + Tailwind** - Avoid other CSS-in-JS solutions
6. **Test locally** - Verify changes don't break routes or state persistence
7. **Consider Firebase APIs** - Understand auth flow and Gemini integration
8. **Document changes** - Update types and comments for clarity

| Hook | Purpose |
|------|---------|
